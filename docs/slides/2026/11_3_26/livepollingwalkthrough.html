Here’s a hand-held walkthrough after you’ve already run quarto add seandavi/quarto-revealjs-live-questions (so you have the _extensions/live-questions/ folder in your project).

The extension turns special divs in your .qmd into live polls/quizzes/word clouds/rating scales that talk to a small server you host yourself. Audience members scan a QR code once per talk and vote on their phones; results update live on the slide. Without a server it falls back to a plain static list (useful for PDFs).

1. Enable the extension and write questions

In your .qmd front matter (or _quarto.yml), add the extension under both filters and revealjs-plugins, plus the server settings:

---
title: "My Talk"
format: revealjs
filters:
  - live-questions
revealjs-plugins:
  - live-questions
live-questions:
  server: https://YOUR-WORKER-NAME.YOUR-ACCOUNT.workers.dev   # fill this in after step 2
  session: my-talk-2026-11-03                                 # unique name for this talk/room
---

Example questions (place them on slides):

## Which language do you use most?

::: {.poll #lang}
- R
- Python
- Julia
:::

## One word for today's lecture?

::: {.wordcloud #mood max-words=2}
:::

## Rate these statements

::: {.likert #feelings scale=agree-5}
- The material was clear
- The pace was good
:::

For quizzes, mark correct answers with task-list syntax: - [x] Correct option. Give each question an explicit #id so editing the text later doesn’t orphan old results.

Render/preview as usual (quarto preview or quarto render). Without a working server it just shows the static lists.

2. Set up a free Cloudflare Workers server (easiest for beginners)

Cloudflare’s free plan is enough. You need a free Cloudflare account and a GitHub (or GitLab) account.

  1. Generate a long random presenter key and save it somewhere safe (you’ll need it later). On macOS/Linux:

    openssl rand -hex 24

    (Or use any long random string of letters/numbers/hyphens.)

  2. Click the Deploy to Cloudflare button on the project’s GitHub README:
    https://github.com/seandavi/quarto-revealjs-live-questions
    (or go directly to the deploy link shown there).

  3. Authorize it to copy the repo into your GitHub account and connect to your Cloudflare account. When it asks for the secret PRESENTER_KEY, paste the value you generated above.

  4. Accept the suggested build/deploy commands. When it finishes, note the Worker URL (something like https://live-questions.youraccount.workers.dev or a name you chose).

  5. Put that exact URL into your Quarto front matter under live-questions: server:.

That’s it for the server. The deploy button sets up a Worker + Durable Object that stores one “room” per session and handles WebSockets. Phones and your slides will talk to it over HTTPS.

Optional later: In the Cloudflare dashboard you can attach a custom domain (Settings → Domains & Routes) if you prefer something prettier than *.workers.dev.

Alternative: Docker (if you prefer self-hosting)

Only do this if you’re comfortable with Docker and can expose the container publicly over HTTPS (required when your slides are on HTTPS).

curl -O https://raw.githubusercontent.com/seandavi/quarto-revealjs-live-questions/main/compose.yaml
curl -o .env https://raw.githubusercontent.com/seandavi/quarto-revealjs-live-questions/main/.env.example
# Edit .env and set PRESENTER_KEY=your-long-random-string
docker compose up -d

It listens on port 8787 by default. You’ll still need a public HTTPS URL that points at it (reverse proxy, Cloudflare Tunnel, etc.).

3. Present

  1. Render or publish your slides (GitHub Pages, Quarto Pub, Netlify, etc.).

  2. Open the deck once in the browser you’ll present from, with the key:

    https://your-slides-url.html?presenter=YOUR-PRESENTER-KEY

    The deck stores the key in that browser’s localStorage, removes it from the address bar, and connects as the presenter. Later visits from the same browser are automatic. Anyone else who opens the deck is a read-only viewer (they see the QR and results but can’t control anything).

  3. Navigate to a question slide → it opens, a QR code appears, and phones can join via the session URL. Results update live.

  4. Useful keys (presenter only):

    • Q – full-screen QR
    • A – reveal correct answer (quizzes) and close voting
    • T – toggle results visibility on the slide

Notes - Phones must reach the server; for real talks use a public HTTPS address. - If your slides are served over HTTPS, the server must also be HTTPS (Cloudflare Workers gives you this automatically). - Do a dry run on the machine you’ll present from. - Use ?session=rehearsal (or any other name) to practice without touching the real room. - Speaker view runs as a viewer, so present from the main window.

That’s the full path from “extension installed” to live polls. The Cloudflare button is by far the least painful option if you’re new to servers. Once the Worker is up and the server: URL is in your front matter, you’re ready to test.

How does ?presenter=YOUR_KEY work?

Here’s exactly how ?presenter=YOUR_KEY works and how to use it.

What the key does

The Cloudflare Worker has one secret: PRESENTER_KEY.
Only a browser that knows that key can control the questions (open them, close voting, reveal answers, reset, etc.). Everyone else is a read-only viewer.

The key is never baked into the HTML, so your published GitHub Pages deck is safe to share. Control is granted only by visiting with the key once.

How you use it (the practical steps)

  1. Generate and store the key (you already did this when deploying to Cloudflare).
    Example: a1b2c3d4e5f6... (the long random string you set as PRESENTER_KEY).

  2. Become the presenter (do this once per browser/computer you will present from):

    • Open your published slides URL and append the key:

      https://yourusername.github.io/your-repo/slides.html?presenter=a1b2c3d4e5f6...

    • The deck will:

      • Accept the key
      • Store it in that browser’s localStorage
      • Remove it from the address bar
      • Connect as the presenter

  3. After that, just open the normal slides URL (no query string).
    That same browser remembers it and is automatically the presenter.
    Other browsers/computers, or an incognito window, will be viewers until you give them the key the same way.

  4. To forget the key (optional):
    Open https://yourusername.github.io/your-repo/slides.html?presenter= (empty value).

Walking an audience through the whole process

You can do a live demo, but a couple of practical notes:

  • For the audience they only need to scan the QR code that appears on a question slide. They never need the presenter key.
  • For you (the presenter), the key step is the one-time ?presenter=... visit. You can do that before the talk, or live in front of them if you want to show the process.
  • Recommended live-demo sequence:
    1. Show the published deck URL (normal link, no key).
    2. Explain “I’m going to become the presenter…” and open the version with ?presenter=YOUR_KEY (you can share the key on screen briefly if you’re comfortable; it’s only for this session).
    3. Navigate to a question slide → QR code appears.
    4. Have everyone scan it and vote.
    5. Show the results updating live.
    6. Demonstrate keys (A to reveal answer, T to toggle results, Q for full-screen QR) if useful.

Quick checklist before you go live with an audience

Once the key is stored in the presenting browser, the rest of the talk is just navigating slides normally — the questions open automatically and results stream in.
