Regarding suggestion 16:

Quarto profiles let one project produce different documents from the same files. For a workshop, student and instructor is the most useful pair: students get the worksheet; you get the version with answers, notes, and executed output.

Official docs: Project Profiles.

What a profile actually is

You keep a shared _quarto.yml, then add extra YAML files named _quarto-<name>.yml. When you render with --profile <name>, Quarto merges that file on top of the base config.

Activation:

quarto render --profile student
quarto render --profile instructor

Or:

export QUARTO_PROFILE=instructor
quarto render

--profile replaces any QUARTO_PROFILE in the environment. You can activate several at once (--profile instructor,prod); for scalar keys the first listed profile wins. If you typo a profile name and there is no matching _quarto-….yml, Quarto silently ignores it.

Four things change when a profile is active:

  1. Extra YAML is merged (execute, format, output-dir, titles, which files to render, etc.).
  2. Optional _environment-<profile> vars are applied.
  3. Content can be shown/hidden with when-profile / unless-profile.
  4. Code can read Sys.getenv("QUARTO_PROFILE") (R) or os.environ["QUARTO_PROFILE"] (Python).

A concrete student / instructor setup

_quarto.yml (shared defaults):

project:
  type: default

profile:
  group:
    - [student, instructor]
  default: student

execute:
  echo: true
  eval: true
  warning: false

profile.group says these two are mutually exclusive, and the first name is the default if nobody passes --profile. That is handy so RStudio / VS Code preview “just works” as the student version.

_quarto-student.yml:

project:
  output-dir: _student

title: "Workshop worksheet"

execute:
  eval: false          # show starter code, do not run solutions
  echo: true

format:
  html:
    output-file: worksheet

_quarto-instructor.yml:

project:
  output-dir: _instructor

title: "Workshop — instructor notes"

execute:
  eval: true
  echo: true

format:
  html:
    output-file: instructor-notes

Then:

quarto render --profile student
quarto render --profile instructor

You get two output folders from one source tree.

Branching inside code with QUARTO_PROFILE

If you would rather not wrap whole chunks in divs:

# hidden solution chunk

Or keep eval: true everywhere and gate prints:

if (grepl("instructor", Sys.getenv("QUARTO_PROFILE"))) {
  print(coef(fit))
}

That is useful when the same chunk should run in both versions but only the instructor output should appear.

Authoring tips so this doesn’t bite you in a live workshop

  1. Set profile.default: student so a casual Render button never dumps solutions.
  2. Put instructor output in a directory that is gitignored or unpublished.
  3. Don’t rely on eval: false alone to hide answers — students can still read the .qmd. Profiles hide rendered content; they are not encryption.
  4. If you use knitr, programmatic chunk options (#| eval: !expr …) remain the most flexible for R-only materials. Profiles are the cleaner route when you also have Python/Julia or want different titles, output dirs, and prose.
  5. Preview: quarto preview --profile instructor to check the teaching version before class.
